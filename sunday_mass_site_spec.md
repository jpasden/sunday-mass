# Sunday Mass Readings & Videos — Project Spec

## Overview

A fully automated static website that displays the **upcoming Sunday's Catholic Mass readings** and a curated selection of **YouTube videos** (full masses, homilies, and music) relevant to that Sunday. The site is regenerated by a cron job running on a shared server (SSH access, no root) with Apache/Nginx serving static files.

---

## Goals

- Show the upcoming Sunday's liturgical identity (e.g., "Fourth Sunday of Lent, Year C")
- Display the full Mass readings for that Sunday, scraped from Catholic.org
- Show up to 3 YouTube videos per category: Full Masses, Homilies/Sermons, Music
- Incrementally accumulate videos across multiple cron runs (new videos merged, none lost)
- Be fully hands-off once deployed — no manual updates required

## Data Flow

```
[cron trigger]
      ↓
[1. Determine upcoming Sunday date]
      ↓
[2. Get liturgical identity]
      Primary:  Scrape label from Catholic.org readings page
      Fallback: python-liturgical-calendar library
      ↓
[3. Scrape readings from Catholic.org]
      (Only re-scrape if Sunday date has changed in data.json)
      ↓
[4. YouTube API: 3 searches]
      - "{Sunday name} Mass {year}"
      - "{Sunday name} homily OR sermon {year}"
      - "{Sunday name} hymns OR songs OR canticle"
      ↓
[5. Merge new video IDs into data.json]
      (Deduplicate by YouTube video ID)
      (Cap each category at 3 displayed, but store all found)
      ↓
[6. Re-render index.html from data.json via Jinja2]
```

## Catholic.org Scraping

### Target URL pattern
```
https://www.catholic.org/bible/daily_reading/?date=20260315
```

### What to scrape
- Liturgical Sunday name/label (e.g., "Fourth Sunday of Lent")
- Each reading: citation + full text
- The liturgical year (A, B, or C) if present on the page

### robots.txt status
✅ Confirmed clear — no content paths are disallowed. Be respectful: add 1–2 second delays between requests.

## YouTube API

### Setup (see separate section below)
- Free tier: 10,000 units/day
- Each search costs 100 units → ~100 searches/day available (far more than needed)

### Search queries (run each cron execution)
```python
queries = {
    "full_mass": f'"{liturgical_name}" Mass {year}',
    "homily":    f'"{liturgical_name}" homily OR sermon {year}',
    "music":     f'"{liturgical_name}" hymns OR songs OR canticle',
}
```

### Per-category behavior
- Fetch top 5 results per search
- Merge into `data.json`, deduplicating by video ID
- Display only top 3 per category in rendered HTML (ranked by view count or recency — TBD)

## Getting a YouTube Data API v3 Key

Follow these steps exactly:

1. Go to [https://console.cloud.google.com](https://console.cloud.google.com) and sign in with a Google account
2. Click **"Select a project"** → **"New Project"** → name it (e.g., `sunday-mass-site`) → **Create**
3. In the left sidebar: **APIs & Services → Library**
4. Search for **"YouTube Data API v3"** → click it → click **Enable**
5. Go to **APIs & Services → Credentials**
6. Click **"+ Create Credentials" → "API Key"**
7. Copy the key shown — paste it into `config.py`
8. (Recommended) Click **"Edit API Key"** → under "API restrictions," restrict it to YouTube Data API v3 only

> ⚠️ Never commit `config.py` to a public git repo. Add it to `.gitignore`.
